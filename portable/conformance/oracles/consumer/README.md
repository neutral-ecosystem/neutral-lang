# Consumer protocol oracles

`boundary.json` owns literal expected outcomes for the
[boundary requests](../../../specs/fixtures/consumer/boundary.json), joined by
unique case ID. Accepted cases state exact resolved types, selected values/roots,
availability obligations, canonical selector tuples or original-byte locations.
Rejected cases state the reader-contract phase and stable `NEU-CONS` code.

These are frozen design oracles, not reports generated by a working consumer
bridge. The fixture harness must compare actual independent reader results,
including atomic failure and redaction invariants. Registration/integrity checks
do not certify producer truthfulness, decoder implementation, target capability
support, authorization, or execution correctness.
